# CYBERGUARD — Cybersecurity Log Analysis and Threat Detection System

> **College Project-Based Learning (PBL) Specification**  
> **Official Project Description:**  
> *"CYBERGUARD is a Java-based cybersecurity log analysis and threat detection system that analyzes system logs using rule-based pattern detection and object-oriented programming principles. A React frontend communicates with a Spring Boot REST API to upload logs, process them using Java-based security rules, and display detected threats, severity levels, statistics, and downloadable reports."*

---

## 1. Project Overview & Purpose

**CYBERGUARD** modernizes the foundational Java Swing log analyzer into an enterprise-grade full-stack web application. It ingests server and security logs (`.log`, `.txt`), executes deterministic regular-expression security rules to detect intrusions and anomalies, calculates security posture metrics, and outputs audit reports (CSV and text formats).

### Key Features
- **Deterministic Rule Engine:** Preserves and reuses the core Java detection logic without black-box AI hallucinations.
- **Full-Stack REST Architecture:** Spring Boot 3.4 REST backend paired with a modern React 18 frontend.
- **Dynamic Cybersecurity Dashboard:** Real-time breakdown of log lines, threat severities, threat categories, and safe vs. suspicious distributions.
- **Incident Inspection & Triage:** Filterable, searchable, and sortable detection table with an interactive Threat Details Modal detailing recommended mitigations.
- **Downloadable Security Reports:** Formatted CSV and Text reports generated by Java `ReportGenerator`.
- **Pre-loaded Sample Ingestion:** One-click testing with bundled `samplelog.txt`.

## 2. Object-Oriented Programming (OOP) Principles

The backend architecture strictly demonstrates fundamental OOP concepts:

| OOP Principle | Implementation in CYBERGUARD |
|---|---|
| **Abstract Class** | `LogAnalyzer` (`com.cyberguard.analyzer.LogAnalyzer`) defines the contract `public abstract ThreatResult analyzeLog(String line, int lineNumber);`. |
| **Inheritance** | `SystemLogAnalyzer extends LogAnalyzer`, specializing pattern matching rules for security signatures. |
| **Polymorphism** | `LogReader` and `ThreatDetectionService` take a polymorphic reference to `LogAnalyzer`, executing the concrete implementation at runtime via dynamic method dispatch. |
| **Encapsulation** | `ThreatResult`, `DetectedThreat`, `LogEntry`, and `AnalysisReport` maintain private fields, immutable accessors, and data integrity safeguards. |
| **Interfaces** | `ThreatDetectionEngine` defines the detection contract; `WebMvcConfigurer` standardizes cross-origin resource sharing. |
| **Collections Framework** | `List<ThreatResult>`, `Map<String, Long>`, `LinkedHashMap` (ordered severities), `TreeMap` (sorted categories), and `Set` (deduplication). |
| **Java I/O Streams** | High-throughput parsing via `BufferedReader`, `StandardCharsets.UTF_8`, Java NIO `Files`, and `PrintWriter` report generation. |
| **Exception Handling** | Custom exceptions (`IllegalArgumentException`, `IllegalStateException`) handled centrally via `@RestControllerAdvice` (`GlobalExceptionHandler`). |

## 3. Supported Threat Types & Detection Signatures

CYBERGUARD supports the 6 core threat types defined in the base project:

| Threat Type | Severity | Regex Signature / Criteria | Recommended Mitigation Action |
|---|---|---|---|
| **SQL Injection** | `CRITICAL` | `(union\s+select\|or\s+1\s*=\s*1\|drop\s+table\|insert\s+into\|select\s+.*?\s+from)` | Immediately isolate session/IP. Enforce parameterized queries (`PreparedStatement`) and least-privilege DB access. |
| **Cross-Site Scripting (XSS)** | `HIGH` | `(<script\|javascript:\|onerror\s*=\|onload\s*=)` | HTML-encode dynamic outputs, enforce strict Content Security Policy (CSP), and audit DOM sinks. |
| **Suspicious Command** | `HIGH` | `(cmd\.exe\|powershell\|/bin/bash\|wget\s+http\|curl\s+http\|rm\s+-rf)` | Quarantine host system, inspect execution tree, and block outbound command-and-control (C2) connections. |
| **Unauthorized Access** | `HIGH` | `(unauthorized\|access\s+denied\|permission\s+denied\|forbidden)` | Audit Role-Based Access Control (RBAC), revoke compromised sessions, and inspect endpoint route guards. |
| **Port Scanning** | `MEDIUM` | `(port\s+scan\|nmap\|multiple\s+ports\|scan\s+detected)` | Block source IP at perimeter firewall and disable unneeded listening ports. |
| **Failed Login** | `MEDIUM` | `(failed\s+(login\|log-in)\|authentication\s+failed\|invalid\s+password)` | Implement account lockout thresholds, require Multi-Factor Authentication (MFA), and rate-limit logins. |

## 5. REST API Documentation

Base URL: `http://localhost:8080/api`

| HTTP Method | Endpoint | Description | Request / Parameters | Response |
|---|---|---|---|---|
| `GET` | `/health` | System health check | None | `HealthResponse` (status 200) |
| `POST` | `/logs/analyze` | Ingest and analyze log file | Multipart `file` (`.log` or `.txt`) | `AnalysisResponse` (status 201) |
| `POST` | `/logs/upload` | Ingest log file (alias) | Multipart `file` | `AnalysisResponse` (status 201) |
| `POST` | `/logs/sample` | Load and analyze bundled `samplelog.txt` | None | `AnalysisResponse` (status 201) |
| `GET` | `/logs/sample` | Retrieve raw text of sample log | None | `text/plain` |
| `GET` | `/reports/latest` | Retrieve latest analysis report | None | `AnalysisResponse` (status 200) |
| `GET` | `/reports` | List all historical reports | None | `List<ReportSummary>` (status 200) |
| `GET` | `/reports/{id}` | Get specific analysis by ID | `id` (path variable) | `AnalysisResponse` (status 200) |
| `GET` | `/reports/{id}/csv` | Download CSV report | `id` (path variable) | `text/csv` attachment |
| `GET` | `/reports/{id}/summary` | Download formatted text report | `id` (path variable) | `text/plain` attachment |
| `GET` | `/statistics` | Get statistical aggregations | Optional `reportId` query param | `StatisticsResponse` (status 200) |

## 6. How to Run the Application Locally

### Prerequisites
- **Java:** JDK 21 or later (`java -version`)
- **Maven:** Apache Maven 3.9+ or use the included `mvnw.cmd`
- **Node.js:** v20+ with npm (`node -v`, `npm -v`)
- **MySQL Database:** Local MySQL Server (e.g., MySQL 8.x/9.x on port 3306)

---

### Step 0: MySQL Database Setup

1. Start your local MySQL server (Service `MySQL92` or default MySQL service).
2. Create the `cyberguard` database (Spring Boot can also auto-create it if enabled):
   ```sql
   CREATE DATABASE IF NOT EXISTS cyberguard;
   ```
3. Verify or adjust database credentials in `backend/src/main/resources/application.properties`:
   ```properties
   spring.datasource.url=jdbc:mysql://localhost:3306/cyberguard?createDatabaseIfNotExist=true&useSSL=false&allowPublicKeyRetrieval=true&serverTimezone=UTC
   spring.datasource.username=root
   spring.datasource.password=sridharshini
   ```

---

### Step 1: Start the Backend (Spring Boot)

Open a terminal in the project directory:

```powershell
cd backend
mvn spring-boot:run
```

*(Alternatively, use the built JAR directly:)*
```powershell
cd backend
java -jar target\cyberguard-backend-1.0.0.jar
```

The Spring Boot backend will start on **http://localhost:8080**.  
Verify by visiting: `http://localhost:8080/api/health`

---

### Step 2: Start the Frontend (React + Vite)

Open a second terminal in the project directory:

```powershell
cd frontend
npm install
npm run dev
```

The React frontend will start on **http://localhost:5173** (or `http://127.0.0.1:5173`).

---

### Step 3: Run the Verification Tests

To run the complete automated test suite (13 unit and integration tests):

```powershell
cd backend
mvn test
```

## 7. College PBL Demonstration Walkthrough

1. **Open the Web Application:**  
   Navigate to `http://localhost:5173` in your browser.
2. **Dashboard Overview:**  
   Observe the clean academic design, cybersecurity status banner, and quick metrics.
3. **Upload Log / Load Sample:**  
   - Click **"Upload Logs"** in the sidebar.
   - Click the **"Load Bundled samplelog.txt"** button (or drag and drop `samplelog.txt`).
   - The system immediately analyzes the file and redirects to the **Analysis** page.
4. **Inspect Analysis Results:**  
   - View the 8 detected threats across 12 lines.
   - Filter by **Severity** (e.g., select `CRITICAL` to see the SQL Injection attempt on Line 7).
   - Filter by **Threat Type** (e.g., select `Suspicious Command` to see Line 11).
   - Use the **Search bar** to query keywords like `powershell` or `admin`.
   - Click the **"Details"** button on any threat to open the **Threat Details Modal**, showing the original log line and actionable mitigation recommendations.
5. **Generate & Download Reports:**  
   - Navigate to the **Reports** tab.
   - Inspect the live, in-browser terminal preview generated by Java `ReportGenerator`.
   - Click **"Download CSV Report"** and **"Download Text Summary"** to verify exported files.
6. **Review OOP Principles:**  
   - Navigate to the **About** page to see the formal explanation of the 8 OOP principles and regular expression rules for project presentation.
